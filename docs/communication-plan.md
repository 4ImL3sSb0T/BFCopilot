# 通信系统实施计划：TCP 日志与 UDP 遥控

## 1. 目标与约定

本计划细化并更新 [App 与 Service 层开环计划](service-open-loop-plan.md) 中的通信部分，服务于左右翼定点与正弦扑翼台架调试。

| 通道 | 首阶段用途 | 数据形式 |
|---|---|---|
| TCP 3333 | ESP-IDF 运行日志输出 | 原始日志文本 |
| UDP 3334 | 遥控、操作应答、配置读写与状态回传 | 自定义二进制帧，一包一帧 |
| USB Serial/JTAG console | 本地启动、运行与故障排查 | 保留现有日志输出 |
| UART0 | 预留串口二进制调试入口 | 复用业务消息，采用 COBS 分帧 |

- 首个验收版本以 TCP 日志和 UDP 遥控为主线，串口业务适配后续接入；不包含 ELRS 接收机。
- 日志连接与遥控会话独立：日志客户端连接、断开、拥塞均不改变控制权和舵机状态。
- 开环控制不依赖 IMU；姿态估计和闭环控制仍按总计划后续推进。
- 默认端口、发送频率、超时和缓冲容量参数化；本文默认值用于台架验证。

## 2. 模块与接口边界

| 模块 | 职责 |
|---|---|
| `bsp/com` | Wi-Fi、TCP/UDP 和 UART 原始收发、连接状态及底层缓冲 |
| `lib/protocol` | 纯 C 的帧编码、解码、CRC、字段序列化及串口流分帧 |
| `service/link/link_log` | ESP-IDF 日志捕获、有界缓存、TCP 客户端管理与转发 |
| `service/link/link_rc` | UDP 接收、通信会话、来源路由、请求去重、协议事件发布、应答缓存与发送 |
| `app/rc_dispatch` | 协议与业务类型转换、向 flight 提交、轮询执行结果、汇总状态并生成应答/遥测 |
| `app/flight` | 控制权、动作许可、最新目标、控制期限、执行结果及停机 |
| 地面工具 | 协议客户端、连续遥控发送、请求管理、状态展示与日志接收 |

- 保留 `link_start()`、`link_stop()`，新增 `link_get_status()` 查询通信统计，以及 `link_receive_event()` / `link_send_message()` 供 app 取事件、发协议消息；日志与遥控两个子模块各自维护状态和资源。公共类型与接口以总计划第 6 节为准。
- `lib/protocol` 不依赖 BSP、FreeRTOS 或业务状态，公开编解码与流解析接口供主机测试。
- `link_rc` 仅发布纯协议消息及通信事件，不包含 flight/monitor 头文件，不调用 app；service、BSP 和 lib 均不得反向依赖 app。
- `app/rc_dispatch` 消费 link 事件，将协议消息映射为 `flight_command_t` / `flight_target_t`，并保留首次板端接收时间；业务参数由 flight 再次校验。配置片段合并、协议错误码转换、监测快照读取和遥测生成均在 app 桥接模块完成。
- `flight` 仅接收逻辑会话标识、命令和期限，不持有 socket 或 `bsp_net_peer_t`；执行结果由 `rc_dispatch` 作为唯一消费者从有界结果队列取出，转换为协议消息后提交 link 发送。flight 不依赖 link 或协议类型。
- link 事件及发送消息携带通信会话编号和代次；桥接保留请求到原通信代次的关联，link 拒绝向已撤销/复用的路由发送旧结果。通信代次与 flight 的业务代次分别维护。
- 连续目标使用最新值邮箱，操作请求使用队列；公共目标提交接口需体现覆盖语义，例如 `flight_update_target()`。
- 通信服务先创建缓冲和任务，再挂接日志回调。停用时先停止远程捕获并恢复原回调，确认在途访问结束后再释放资源。

```text
接收：UDP → link_rc → link_receive_event() → app/rc_dispatch → app/flight
返回：app/rc_dispatch 轮询 flight 结果/快照 → link_send_message() → link_rc → UDP
监测：app/rc_dispatch 读取 monitor 快照 → 生成协议遥测 → link_send_message()
```

## 3. TCP 日志

### 捕获与发送

```text
ESP_LOGx → 日志回调 → 有界日志队列 → 低优先级转发任务 → BSP TCP 发送队列
                  └→ 原有本地日志输出
```

- 使用 `esp_log_set_vprintf()` 保存并包装原输出函数，正常运行日志同时保留本地输出和 TCP 副本。
- 回调可能由多个任务调用，必须可重入；用独立的 `va_copy` 分别完成本地输出与远程格式化。
- 远程捕获分支不分配堆内存、不访问网络、不等待队列空间；本地输出保留原有行为，其耗时仍计入控制任务调度评估。
- 首版日志片段容量取 256 字节，队列深度取 16；超长内容截断并计数，队列满时丢弃新片段并计数。
- 回调输入按文本片段处理，不假定一次调用对应完整日志行；TCP 保留片段顺序，客户端增量显示。
- 转发任务将丢弃、截断的累计数量作为明确的文本提示发送，发送提示不再调用 `ESP_LOGx`。
- 首版仅服务一个日志客户端。其他 TCP 会话有界地读取并丢弃输入，不发送日志；当前客户端退出后才选取后续会话。
- 转发任务使用 `bsp_net_send(..., timeout_ms=0)`；拥塞时丢弃当前远程片段，不等待、补发或无限缓存。
- 无客户端时直接丢弃远程副本；重连从新日志开始，不保存启动日志历史。
- 回调、转发及其错误处理路径不再次打印日志，避免递归及错误日志循环。

### 覆盖范围

- 首阶段保证安装回调后的正常任务日志转发。启动早期、panic、ISR 或特殊日志路径不承诺进入 TCP，故障排查保留 USB console。
- TCP 保持文本输出，不混入遥控业务应答，也不接受文本控制命令；显示端应能够处理日志中已有的 ANSI 字符。
- TCP 正常连接时按顺序转发；应用层拥塞丢弃通过统计体现，不把网络日志作为完整无损记录。

## 4. UDP 业务协议与遥控

### 帧与消息

- 使用新协议版本，帧统一包含识别标志、版本、消息类型、载荷长度、会话编号、帧序号、请求编号、载荷和 CRC32。
- 采用小端逐字段序列化，不直接发送 C 结构体；CRC 使用 CRC-32/ISO-HDLC，覆盖除 CRC 字段外的完整原始帧。
- 首版载荷上限取 256 字节；实际长度必须与头部一致，空包、超长包、未知版本和错误 CRC 均丢弃并分类计数。
- 连续控制以一包表达完整目标：定点或扑翼模式、左右目标翼位或频率/左右幅度/中位/相位差。翼位沿用总计划的归一化定义。
- 业务消息覆盖建立会话、获取/释放控制权、目标更新、解锁、启动、停止、急停、清故障、标定、配置查询/修改/保存和状态查询。
- 协议错误码与 ESP-IDF 解耦，至少区分参数错误、状态不允许、控制权冲突、资源忙、会话失效和内部执行错误。
- 实现编解码前形成配套协议说明，固定字段宽度、消息编号、载荷布局、数值单位及测试报文；C 与 Python 共用测试向量。

### 连续目标与操作请求

| 类型 | 规则 |
|---|---|
| 连续目标 | 默认 50 Hz 发送；每包包含完整当前目标，最新有效目标覆盖旧值，不重传旧目标，不逐包 ACK |
| 操作请求 | 带非零请求编号，顺序执行并返回实际结果；重试沿用同一请求编号 |
| 状态回传 | 默认 10 Hz 向当前遥控会话来源回传最新快照；不重传历史状态 |

- 目标消息与操作请求分开处理；设置目标不隐式解锁或启动。
- `ACCEPTED` 仅代表正在执行，`OK` 表示业务处理完成，`REJECTED` 返回未执行原因；地面端不能把入队成功当成动作完成。
- 保存等耗时操作可先返回 `ACCEPTED`，随后返回最终结果；运行期间拒绝配置修改和保存。
- link 与 app 桥接之间的普通操作使用有界队列，连续目标按有效会话保留最新值；急停及会话撤销独立锁存，不受普通队列容量影响。接入缓冲不改变 flight 内部操作队列和最新目标邮箱的语义。
- 每个会话保留有界的近期请求记录，识别执行中及已完成的重试；同一请求编号对应不同内容时拒绝执行。
- 重试不刷新操作本身的有效期。淘汰后的旧请求不得再次执行，使用请求编号高水位拒绝过旧请求；编号耗尽前重新建立会话。
- 目标帧序号独立维护递增高水位，拒绝重复与乱序；重发操作可使用新帧序号，但请求编号保持不变。
- 结果表示固件状态或输出已更新，不表示舵机物理到位；遥测区分命令翼位、输出脉宽与未来可能增加的实测翼位。

### 控制权、期限与失联

- 同时仅有一个控制者，绑定板端分配的会话及实际 UDP 来源 IP/端口；地址变化后必须重新建会话，不自动迁移控制权。
- 建立会话与获取控制权均不自动解锁或启动；操作成功后才推进地面端状态。
- 控制包承担持续在线证明，不额外要求运行阶段发送独立心跳。查询、日志活动、非法包和操作重试均不延长控制期限。
- 默认连续 500 ms 没有有效控制目标时，由 `flight` 在下一个控制周期进入故障停机，关闭输出及电源；50 Hz 调度下台架目标为最后有效目标后 520 ms 内完成停机调用。
- 使用板端单调时间签发的短期控制凭据，地面端随控制帧回传；期限不依赖两端时钟同步，也不能由地面端自行延长。
- 凭据默认有效 500 ms，板端每 100 ms 发送新凭据；旧凭据只在原期限内有效。没有可用新凭据时地面端停止继续控制并提示失联。
- `flight` 执行前再次检查会话与凭据，控制截止时间不晚于最近有效目标接收时间加 500 ms，也不晚于该目标所用凭据的到期时间。
- 超时撤销会话及待执行动作，迟到目标或操作不能恢复运行；恢复后重新获取控制权、解锁和启动。
- 急停在 link 接入和 flight 执行两处均使用独立锁存路径；`rc_dispatch` 优先将安全事件转交 `flight_latch_estop()` / `flight_revoke_session()`，不受普通操作队列满影响。允许格式合法的急停请求绕过控制权竞争，但不允许清故障或启动绕过控制权校验。
- 状态回传包含会话、控制状态、故障、最后接受的控制序号、接收间隔及当前可用凭据，向该会话的实际来源发送。

## 5. 调度、资源与地面工具

- `link_rc` 任务负责有界轮询 UDP、解析、通信会话/去重维护、发布事件及发送协议消息；每轮限制报文处理数，不等待 app 执行结果或遥测生成。
- `app/rc_dispatch` 独立任务先处理安全事件和已有执行结果，再有界提交操作/最新目标，默认每 100 ms 汇总 flight/monitor/link 快照并生成遥测；查询结果和提交发送均不阻塞，不在该任务等待配置作业。
- 应答先于普通遥测发送；接受操作前为接入、业务执行和结果缓存预留容量，满时拒绝新的普通操作，不能静默丢失已接受操作的完成结果。桥接发送结果遇忙时保留重试，link 缓存最近结果供原请求编号查询或重试获取。
- `flight` 的 50 Hz 控制任务自行检查失联，即使日志或遥控通信任务停止进展，也能够执行停机。
- 日志任务优先级低于 link_rc、app/rc_dispatch 和控制任务，控制任务优先级最高，各任务工作量有界；TCP 和 UDP 仍共享 Wi-Fi 与现有 BSP 网络调度资源，必须测量混合负载。
- Wi-Fi 连接管理不阻塞控制任务。Wi-Fi 中断时 link 清理日志客户端及 UDP 会话并锁存失效事件，由 rc_dispatch 转交 flight 撤销；事件未及时分发时仍依赖 flight 自身期限停机。恢复网络不恢复动作。
- app 在 link 启动后启动 rc_dispatch；退出时先禁止桥接提交新运动操作并确认 flight 停机，再停止桥接、link 和其余模块。Wi-Fi 关闭时不启动 link/rc_dispatch，flight 保持无控制者的停机状态。
- 对已断开的 TCP 会话有界排空并丢弃尾部，满足 BSP 的槽位复用约定，不把旧连接缓存发送给新客户端。
- 地面端先实现 CLI，再接 GUI；协议、UDP 客户端和 TCP 日志接收分别封装，CLI/GUI 共用业务客户端。
- 连续控制发送与日志接收独立运行，地面端必须具备显式停止发送的状态；本地输入源失效、会话过期或状态回传长期中断后，不能后台持续发送旧目标。
- link 通信统计至少包括合法包、CRC/长度错误、重复/乱序拒绝、请求去重、发送拥塞、日志丢弃/截断及最后合法报文接收时间；业务过期拒绝和最后有效控制接收时间来自 flight，由 rc_dispatch 汇总，不能用解码成功时间代替业务接受时间。

## 6. 实施顺序与验收

1. **协议与主机测试**：固定协议说明，实现 C/Python 编解码、固定报文互通及输入边界测试。
2. **TCP 日志**：实现回调捕获、日志队列、客户端选择和转发，验证本地输出、满队列、慢客户端与重连。
3. **UDP 遥控**：实现 link 会话、去重、事件/发送接口和 app/rc_dispatch 桥接；先用业务替身验证，再接 app/flight 的控制权、最新目标、操作请求与应答。
4. **期限与状态**：加入凭据、执行前检查、失联停机、10 Hz 状态回传及地面端状态管理。
5. **台架与混合压力**：先断开舵机验证行为，再完成单侧和双侧定点、扑翼及故障测试。

必须覆盖的测试场景：

- C 与 Python 对同一组报文生成一致字节，CRC、长度、消息类型及数值单位一致；NaN、无穷值和越界控制被拒绝。
- 丢包、重复、乱序及延迟控制帧不会导致补执行旧目标，重复操作只执行一次。
- 会话、IP/端口、凭据及序号不匹配不会更新目标或延长控制期限；超时后迟到报文不会重新启动。
- app 桥接保留首次板端接收时间；link 接入普通队列满时仍交付急停/撤销，旧通信代次结果不会发给新会话，结果发送拥塞不丢最终结果。
- 检查头文件与组件依赖：link/lib/BSP 不依赖 app，link 不依赖 monitor；flight/rc_dispatch 源文件由 app 组件注册。
- 不启动日志客户端、主动关闭日志窗口、客户端停止读取及日志队列满时，遥控行为保持正确。
- link_rc 或 app/rc_dispatch 任务停止处理、遥控端退出、无线断开时，由 `flight` 独立完成期限检查与停机。
- 日志回调并发调用、长日志、连续日志、连接反复建立/退出均无递归、死锁、无界分配或资源泄漏。
- UDP 遥控 50 Hz、状态 10 Hz，与持续 INFO 日志及慢 TCP 客户端同时运行至少 10 分钟，记录控制间隔分布、超时次数、队列与堆/栈余量；不得把非预期失联或控制超时判为通过。
- 固定 50 Hz 调度下，主动停止遥控后停机调用在约定的 520 ms 内发生；另用示波器验证 PWM 及电源关断，分别记录软件状态与物理输出延迟。
- 无 IMU时仍可开环运行；Wi-Fi 关闭配置仍能构建并保留本地 bring-up；现有网络主机回归通过。

现有 [2026-10-24 台架记录](net-test-2026-10-24.md) 含秒级延迟及持续压力失败结果，实施时保留原记录，并另写本方案的报文长度、负载、截止时间和测试结果。
