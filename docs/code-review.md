# 底层与台架代码审查（2026-10-13）

本轮覆盖 BSP 的 MCPWM/LEDC/RMT 调用、SPI/I2C/ADC 驱动、台架命令和 TCP 控制台、
Python 上位机及烧录脚本；使用 CodeGraph 定位调用链，并对照本机 ESP-IDF 6.0.2 实现。
以下为确认的缺陷及修复，不代表已经完成实物波形、传感器供电或飞行验收。

| 优先级 | 触发与原行为 | 修复 |
|---|---|---|
| 高 | WS2812 编码开头的 reset 符号 duration1=0，混入 RMT 终止时长，后续颜色数据无法可靠输出 | reset 分成两个非零低电平段，保持总计50 µs；回归检查全部25个符号与 GRB 位序 |
| 高 | RMT 等待超时后返回，外设仍可能引用已失效的栈内 RGB 帧 | 使用静态帧，在锁内先等待上次传输完成，再修改帧；超时保持原帧 |
| 高 | `hw gpio 18` 本应读取，却执行 gpio_config(INPUT)，破坏 PWM 输出配置 | 无操作参数时只读电平，不改 GPIO 配置；明确 in/out 才配置，并校验有效 GPIO/输出能力 |
| 中 | 舵机释放失败前就将 debug_active 标为真；停止失败却清掉状态 | 仅驱动成功后提交状态；周期更新的释放错误向上传递 |
| 中 | `hw pulse off`、`servo off`、`hw led off`、`hw buzzer off` 忽略错误并打印成功 | 返回实际驱动错误，保留两侧各自结果 |
| 中 | 蜂鸣器忽略 duty 更新、停止及调度错误，调度失败可留下持续响声；定时回调与新命令竞争 | 检查错误、失败清理，互斥串行控制；已停止或新定时尚未到期时忽略旧回调 |
| 中 | 固件允许30秒 stream，上位机固定8秒超时；命令失败仅靠 ESP_ERR_ 文本识别 | stream 允许35秒；TCP 上报命令退出值，上位机识别 ESP_FAIL、失败状态与语法错误 |
| 中 | UART 与 TCP 可同时执行硬件命令，公用静态输出缓冲，UART 输出可混入 TCP 响应 | 台架命令统一加运行锁；输出缓冲改为每次调用独立，按当前任务区分 TCP 输出 |
| 中 | TCP send 可能只发送部分数据，超长命令会截断后执行 | 补发剩余字节，设置发送超时；丢弃超长整行，不执行截断内容 |

已对照 SPI 命令读写位、字节长度、模式和引脚、I2C 地址与返回值处理、ADC 有效标志、
烧录入口与退出码。本轮未确认另一个足以解释 IMU/I2C 无应答的参数错误。
此前“已排除驱动问题”的表述过强：两份驱动现象相同只能作为排查线索，仍需实际抓取
SPI 时序并测 U3/U5 的 VDD/VDDIO 和共地。原理图网络不等于实物连通性证明。

回归包含 MCPWM 强制动作失败注入、RMT 编码与超时后帧保持、蜂鸣器 duty/定时失败、
旧回调、stream 超时设置及上位机失败显示。网络发送/双控制台和 GPIO 配置仍需实物验证。
不宣称全项目无缺陷；无线配对、带载过流、传感器通信与断电能力仍按既有台架清单验收。

验证结果：6 个 C 主机测试套件、19 个 Python 测试通过；台架、飞控、遥控端三种
ESP-IDF 固件构建通过，`git diff --check` 通过。本轮未重新烧录或测量实物信号。
