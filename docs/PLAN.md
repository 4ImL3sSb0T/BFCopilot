# 仿生蝴蝶双舵机飞控开发计划

> 文档状态：需求澄清完成后的开发指导基线，2026-10-07
>
> 目标平台：用户当前蝴蝶控制板（版本号待记录，沿用原引脚）+ ESP32-C6 飞控 + ESP32 遥控端
>
> 软件基线：ESP-IDF 6.0.2，C 语言
>
> 文档用途：供后续 AI 或开发者按阶段实现、测试和验收。所有尚未实测的数值必须保持为参数或待定项，不得直接当作可飞行限制。

## 1. 已确认约束

### 1.1 硬件

- 电池：2S 锂电，满电 8.4 V；具体型号、容量、截止电压待实测记录，飞控必须监测电池电压。
- 舵机：PTK7465，位置舵机，机械范围 180°，控制频率 333 Hz；用户确认支持 8.4 V、可接现有舵机电源。
- 舵机电流：56 mA 为空载电流，不是运行上限或堵转电流；堵转电流必须台架测量。
- 左右各一只舵机：左 PWM `GPIO18`（U1 模块焊盘24 → H1.3），右 PWM `GPIO19`（焊盘25 → H2.3）；2026-10-13 在线原理图已核对。
- 保留电池、电流检测。资料列出 LSM6DS3TR-C、SPA06-003 和 INA199；驱动按这些器件规划，投用前核对当前板的实装情况。
- 用户明确指出移交资料中的 v1 是老版本；当前板沿用原引脚，不等于沿用所有电源参数或全部旧版问题。
- 当前板没有舵机电源 MOS 控制；本版本不能假设可以软件断电。下一版仅预留软件接口和需求，不分配实际 GPIO、不修改本版 PCB。
- 本任务禁止改板，交付范围为开发计划；硬件不符合上电条件时记录阻塞项，后续 AI 不得自行修改原理图或 PCB。
- 当前仓库是 ESP-IDF 空工程，只有 `main/main.c` 和组件注册文件，需要从基础工程搭建全部固件模块。

### 1.2 机械和控制

- 机械参考：费斯托（Festo）仿生蝴蝶。尚无具体机构图、尺寸、运动录像或版本资料，本计划不假定复刻了参考产品的全部机构。
- 当前只确定左右两侧各一只位置舵机，舵机角度到翅膀扑动角度的关系未知。
- 首版开环目标：直接实现完整扑翼动作，并通过机械测试建立前进、转向、升降的控制映射。
- 首版不能假定存在翅膀角度反馈；翼角、扑翼幅度、相位和机构零位必须通过测量标定。

### 1.3 通信和安全

- 遥控端也是 ESP32；电脑通过 USB 串口连接遥控端，再由遥控端使用 ESP-NOW 控制飞控。
- 飞控必须有显式解锁、急停、失联检测和故障锁定。
- 已确认的失联动作：立即停止扑翼，回到实测安全角度；进入锁定状态，恢复通信后不能自动恢复，必须重新解锁。
- 用户确认 PLAN 同时覆盖遥控端固件、USB 串口协议、ESP-NOW 协议及最小上位机调试工具。
- 用户确认闭环优先级：先 IMU 姿态估计/遥测，再评估姿态稳定；高度控制后置。
- 文档为中文，位于 `docs/PLAN.md`。验证涵盖台架、系留和自由飞行，用户未提出额外重量或场地限制。
- ESP-IDF 6.0.2＋C 是依据当前工程采用的实现基线；暂不规划 OTA，未来如需要另行评审。

## 2. 关键假设和待确认项

以下项目暂不阻塞软件骨架，但在进入动力测试和自由飞行前必须闭合：

1. PTK7465 的额定供电范围、PWM 脉宽范围、最小/最大有效角度、堵转电流、堵转持续时间和实际响应时间。
2. 2S 电池的截止电压、容量、最大放电电流；当前 PCB 的实际分压比、分流电阻、INA199 增益和供电测试结果。
3. 机械零位、舵机安装方向、连杆传动比、翅膀实际角度范围、左/右相位关系和扑翼频率上限。
4. 遥控端 ESP32 的具体型号、USB 实现和天线；当前不要求实体摇杆，电脑为主控制入口，游戏手柄可后续适配。
5. 用户尚未给出控制距离、允许延迟、最大扑翼频率和飞行性能指标。这些指标先作为测试输出，不写成已经满足的承诺。

上述未知项已足够转为实验任务，无需为了写软件骨架继续追问。安全角度、舵机脉宽端点、电池/电流阈值必须标记为“未标定”，不能用猜测的数值解锁带翼运行。

在这些数据未确认前，所有默认值均只能用于限功率台架测试：不得直接用于自由飞行。

## 3. 总体架构

```text
电脑上位机
    │ USB CDC/USB-Serial（控制、调参、遥测、日志）
    ▼
ESP32 遥控端
    │ ESP-NOW（配对、控制帧、状态/遥测帧）
    ▼
ESP32-C6 飞控
    ├── 安全状态机（锁定/待解锁/运行/急停/故障）
    ├── 参数与校准存储（NVS，带版本和 CRC）
    ├── 333 Hz 双舵机 PWM 输出
    ├── 扑翼轨迹发生器（开环）
    ├── IMU SPI 采样与姿态估计
    ├── 气压计 I2C 采样（后置高度功能）
    ├── 电池/舵机电流 ADC 采样
    └── USB 日志、遥测和故障记录
```

### 3.1 固件分层

按 app、service、driver、bsp 四层组织，构建注册集中到每层，避免把控制、安全、通信塞进入口：

```text
src/app/                # 飞控/遥控入口、flight、bf_console
src/service/            # parameter、safety、flapping、protocol、radio、telemetry
src/driver/             # servo、sensors、espnow、ST 官方驱动
src/bsp/                # board 引脚/能力/指示、common CRC/故障词汇/运行锁
test/bench/src/app/      # 独立台架入口、hwtest、网络控制台
tools/station/          # Python/Tkinter 桌面窗口、TCP 传输
```

依赖方向为 app → service → driver → bsp，下层不能引用上层头文件。
驱动初始化由应用注入配置；ESP-NOW 字节传输与协议校验/排队分开。
根工程通过 `BF_REMOTE` 选择入口，共享同一协议定义；
独立台架工程只编译板级、器件、参数及自身应用。
架构细节和桌面上位机启动方式见 `docs/architecture.md`。

### 3.2 任务与时间基准

| 执行单元 | 初始设计 | 约束 |
|---|---|---|
| 舵机 PWM 外设 | 两路同频 333 Hz | 硬件持续生成脉冲，避免软件逐脉冲翻 GPIO |
| 轨迹/安全控制任务 | 约 333 Hz，实际周期据实测确定 | 单一任务拥有舵机目标写入权；每拍先检查安全，再计算轨迹 |
| ESP-NOW 回调 | 仅复制短帧/入有界队列 | 不做 NVS、日志打印、传感器读取或轨迹计算 |
| 通信解析任务 | 按消息唤醒 | 校验来源、会话、序号、TTL 后发布最新控制快照 |
| IMU 采样任务 | 初始考虑 208/416 Hz ODR | 按器件支持的离散档位选择，与轨迹更新频率区分 |
| 电源采样任务 | 电池约 20 Hz；电流约 100 Hz 起评估 | RC 带宽和 ADC 调度决定能检测哪些瞬态 |
| 遥测任务 | 初始 20 Hz | 固定大小快照；背压时丢遥测，控制和急停保持响应 |
| 参数/日志任务 | 低优先级 | 运行时禁止擦写参数、长时间阻塞和无界分配 |

使用单调时钟和实际 `dt` 推进相位。不得把 RTOS tick 当成能精确表达 1/333 秒的时间基准。需要时用硬件定时器或高分辨率定时器通知任务；中断中只发通知。ESP32-C6 按单核调度规划，不假设可将 Wi-Fi 和飞控分别绑定两个核心。

相位 `phi = wrap(phi + 2*pi*f*dt)`，频率切换保持相位连续；命令是频率/幅度等参数，而非要求无线逐个传输舵机 PWM。任务丢拍时禁止快速补发多次动作；超预算则记录并按配置进入锁定。

## 4. GPIO 和外设基线

以 2026-10-13 在线原理图回读为引脚基线（来源和模块焊盘对应关系见 hardware-baseline.md §9），代码必须集中定义，禁止在业务代码散落魔数：

| 功能 | GPIO/接口 | 处理要求 |
|---|---:|---|
| 左舵机 PWM | GPIO18（U1.24 → H1.3） | MCPWM，两路共用时间基准 |
| 右舵机 PWM | GPIO19（U1.25 → H2.3） | 同左；方向由参数决定 |
| IMU SCK/MOSI/MISO/CS | GPIO7/GPIO15/GPIO14/GPIO6 | 按当前修正版 v1 网表核对后启用 SPI |
| 气压计 SCL/SDA | GPIO4/GPIO5 | I2C，设备地址默认 `0x77` |
| 电池 ADC | GPIO0/ADC 通道 | 按实测分压比校准，2S 满电不得超过 ADC 允许范围 |
| 电流 ADC | GPIO1/ADC 通道 | INA199 输出；按实际分流器和增益校准 |
| 蜂鸣器 | GPIO3 | 仅用于状态提示，不能阻塞控制任务 |
| WS2812 | GPIO23 | 用于状态灯；异常状态必须可见 |
| USB | GPIO12/13 | 飞控调试/日志能力按板级实际 USB 支持验证 |

注意：IMU 的主 SPI、USB 供电等问题在移交包不同版本中有冲突。用户只确认引脚相同，不等于确认每份导出参数相同。当前实物及用户认可的当前网表优先；旧报告用于建立核验清单，不能用于自动推断需要改板。

### 4.2 下一版电源 MOS 软件预留

定义板级能力 `servo_power_switch_available` 及 `servo_power_enable/disable()` 接口。当前板该能力恒为 false，调用返回“不支持”并记录状态；不得用假 GPIO 或停止 PWM 伪装已切断电源。

下一版接口需求包括：默认断电、复位/棕断时硬件关断、有效电平、上电等待、泄放时间、电流容量、反灌及故障处理。待硬件确定后再填 GPIO 和电气参数，本任务不实现或修改该电路。

## 5. 开发阶段和出口条件

### 阶段 0：资料和安全基线

任务：

- 固化当前实物的原理图/网表/BOM来源、数据手册和实际焊接版本；资料不一致的项目用照片或测量闭合。
- 用万用表确认 GPIO18/19 到 H1/H2 PWM、舵机电源极性和公共地。
- 确认 2S 电池直接接入路径、满电实测电压和电池 ADC 分压。
- 用户确认额定 8.4 V；用手册/铭牌补证，测量 PWM 要求、空载/带载电流；堵转测试仅在有电流限制、明确测试时长和可人工断电条件下执行。
- 建立“禁止带翅膀通电”的初始安全规则，首次测试拆下连杆或使用限位工装。

出口条件：

- 电源和信号连接有照片/记录；
- 舵机允许电压不低于实际 `VCC_Servo`；
- 电池 ADC 在满电、欠压阈值和断电时读数可区分；
- 已知带载电流边界；堵转数据已获取或明确标为未验收，不能据空载电流设过流阈值。
- 若实物 ADC 满电过压、电源不稳定或载流能力不足，停止电池动力测试；仅继续断开电池/舵机的供电验证及纯软件工作。禁止以“会用软件保护”为理由继续上电。

### 阶段 1：工程骨架和板级驱动

任务：

- 建立 ESP-IDF 工程组件结构、统一编译选项和错误码。
- 实现 GPIO、日志、定时器、LED、蜂鸣器和看门狗初始化。
- 实现 NVS 参数存储：版本、长度、CRC、默认值、恢复出厂。
- 实现舵机 PWM 驱动，启动先保持无有效脉冲；只有已保存有效校准且人工允许受控使能时，才移动到安全角度，始终禁止自动扑翼。
- 实现 ADC 电池/电流采样和简单滑动滤波。

出口条件：

- 冷启动、复位、看门狗和异常日志可重复；
- 两个舵机能独立到达标定角度，停止后不会产生意外往复；
- 参数损坏时自动使用安全默认值并报告故障。

### 阶段 2：舵机标定和单侧台架测试

任务：

- 以 333 Hz 固定刷新周期输出 PWM；实际舵机若不接受该频率，暂停测试并记录，不能默默换频率。333 Hz 的周期约 3003 µs，与扑翼频率无关；每个脉冲必须短于周期并留低电平裕量。
- 标定“脉宽—舵机角度”表，不默认 500–2500 µs、1000–2000 µs或线性 0–180°；180° 是标称范围，不是装翼后的可用行程。
- 分别测量左/右方向、死区、响应延迟、重复性、端点和堵转趋势。
- 实现角度限位、速度/加速度限制和软启动。
- 保存每只舵机独立的零位、方向、最小安全角度、最大安全角度和中心角；校准有效位与数据一起保存，未标定禁止带翼解锁。

出口条件：

- 拆除翅膀或使用无载工装时，100 次往返无越界、无异常复位；
- 左右舵机角度误差和响应延迟有记录；
- 已确定“安全翼位”，供失联和急停使用。

### 阶段 3：开环扑翼轨迹

任务：

- 先实现参数化轨迹，不把机械映射硬编码成单一公式。
- 轨迹参数至少包括：频率、左/右幅度、公共中心角、左右相位、左右偏置、启动/停止斜坡。
- 支持两种模式：
  - 单舵机调试：直接设定左右目标角；
  - 扑翼模式：根据统一相位时钟生成左右轨迹。
- 首版用正弦轨迹启动机构辨识，并保留平滑分段曲线或查表实现。定义机体语义的翼坐标 `qL=C_L+A_L*g(phi)`、`qR=C_R+A_R*g(phi+delta)`；安装镜像通过独立方向/零位映射处理，不能混淆“电气同向”和“左右翼对称扑动”。
- 验证全相位行程：中心与幅度组合不能使任一输出越过安全角度；异常命令在入口拒绝，最终执行层再夹紧。要求速度上限满足最大 `2*pi*f*A`，加速度上限满足最大 `(2*pi*f)^2*A`，最终边界依据带载测试。
- 所有运行参数先经过范围检查、斜坡限制和安全状态检查。

推荐的抽象接口：

```c
typedef struct {
    float frequency_hz;
    float amplitude_left_deg;
    float amplitude_right_deg;
    float center_left_deg;
    float center_right_deg;
    float phase_offset_deg;
    float differential;
} flapping_command_t;

esp_err_t flapping_start(const flapping_command_t *command);
esp_err_t flapping_request_safe_return(void);
esp_err_t flapping_set_manual_angles(float left_deg, float right_deg);
```

停止/回位是非阻塞状态请求；状态机在后续控制拍推进，不允许接口内部等待舵机运动完成。

出口条件：

- 在拆翅、限位和系留条件下可重复启动、运行、停止；
- 频率、幅度、差动改变不会产生突变；
- 333 Hz 输出任务的周期抖动有统计，控制任务不能被日志或 ESP-NOW 阻塞。

### 阶段 4：遥控链路和电脑串口

任务：

- 遥控端负责 USB 串口接收电脑命令、维护本地输入状态、发送 ESP-NOW 控制帧。
- 飞控只接受已配对遥控端的控制帧；控制帧带协议版本、会话、序号、有效期和命令。
- 配对信息和密钥写入 NVS；开发模式也必须有显式配对步骤，不能接受任意广播控制。
- 使用 ESP-NOW 加密能力；密钥、MAC 白名单和配对状态不得写入普通日志。
- 飞控返回状态/遥测帧：安全状态、解锁状态、舵机目标/实测代理值、扑翼参数、电池电压、电流、IMU 健康、RSSI、丢包率、故障码。
- 控制链路与日志链路解耦：通信堵塞、USB 拔出或电脑无响应不能停止飞控安全任务。
- 同时监测电脑→遥控端和遥控端→飞控两段控制有效期。遥控端不能无限重复最后一条电脑命令作为新命令；上游过期应立即发故障/停止命令，并停止发布运行控制帧。

控制帧逻辑字段（准确线格式见第 6 节）：

```text
magic | protocol_version | vehicle_id | session_id | sequence | ttl_ms |
arm_state | emergency_stop | mode | flap_frequency |
amplitude | differential | center_trim_l | center_trim_r |
command_crc
```

状态帧建议字段：

```text
magic | protocol_version | sequence_echo | uptime_ms |
safety_state | fault_flags | battery_mv | servo_current_ma |
imu_health | pressure_health | flap_phase | servo_targets |
rssi | rx_age_ms | dropped_frames | telemetry_crc
```

初始台架配置：控制帧 50 Hz、状态帧 20 Hz、电脑命令超时 150 ms、飞控有效控制帧超时 150 ms、控制帧 TTL 100 ms。它们是未验收初值，最终依据实际系统调度、丢包和故障响应时间调整；不能为了防止报警无限增大超时。

出口条件：

- 正常控制、重复帧、乱序帧、旧序号、CRC 错误、配对失败均有明确结果；
- 断开电脑 USB、关闭遥控端、遮挡无线链路都能触发同一失联安全状态；
- 恢复链路后不会自动解锁或自动恢复扑翼。

### 阶段 5：安全状态机

状态定义：

```text
BOOT_LOCKED
  ├─ 必需项自检通过 + 建立会话 ─> READY_LOCKED
  ├─ 自检失败 ─> FAULT_LATCHED
READY_LOCKED
  ├─ 显式解锁 + 条件满足 ─> ARMED
ARMED
  ├─ 正常控制 ─> ARMED
  ├─ 急停/失联 ─> SAFE_RETURN_LOCKED
  ├─ 过流/电源故障/看门狗等 ─> FAULT_LATCHED（按故障表动作）
SAFE_RETURN_LOCKED
  ├─ 舵机回安全角度并保持 ─> LOCKED
LOCKED
  ├─ 人工清除故障 + 重新建立有效会话 ─> READY_LOCKED
FAULT_LATCHED
  └─ 故障解除 + 显式清除 ─> READY_LOCKED；持续致命故障仅允许诊断
```

安全规则：

- 上电永远锁定；PWM 初始化期间不得输出可能造成大动作的随机占空比。
- 解锁需要有效通信、电池/电流检测有效且在允许范围、舵机标定有效、无急停锁存。开环模式对 IMU/气压计的健康要求与闭环模式分开，气压计离线不得无条件阻塞角度台架调试。
- 失联判定使用“最后有效控制帧年龄”，不能仅依赖 ESP-NOW 回调是否触发。
- 失联/急停顺序：停止产生扑翼轨迹 → 按受限速度移动到安全角度 → 锁定 → 记录事件。
- 当前板没有舵机电源 MOS，停止 PWM 不等于断电；必须在台架上验证舵机是否继续保持力矩，状态中报告 `NO_POWER_CUTOFF` 能力限制。
- 电压过低、过高、舵机过流、ADC 饱和、IMU 丢失、任务看门狗和参数 CRC 错误均应进入故障策略。
- 急停命令应比普通控制命令优先处理，并在飞控本地锁存。

| 故障 | 检测依据 | 动作/限制 |
|---|---|---|
| 无线失联/电脑命令过期/人工急停 | 本地单调计时、有效急停帧 | 立即停止周期轨迹，受限速度回标定安全角，锁存；“立即”指停轨迹，不指瞬移到角度 |
| 舵机过流/疑似卡住 | 校准后电流、持续时间、ADC 饱和 | 优先停止继续推进负载；不得强行回位加重堵转。保持/禁 PWM 行为必须台架选择；人工断电提示，不能承诺软件切电 |
| 欠压 | 滞回、滤波及持续时间 | 警告→锁定回位仅在电源仍足够时执行；棕断无法保证回位，禁止重新解锁 |
| 输入过压/不可靠 ADC | 参数、电气核验及运行检测 | 禁止启动动力；软件检测不能保护已经超压的 ADC 引脚 |
| 开环 IMU/气压计离线 | 设备 ID、总线/数据年龄 | 报警并禁用依赖它的功能；是否继续开环依据已验证模式条件 |
| 姿态闭环 IMU/估计失效 | 数据年龄、饱和、估计有效性 | 停止闭环；只允许预先验证的降级策略，否则停止扑翼并锁定 |
| NVS 损坏/未标定 | 版本、CRC、范围、有效位 | 无动力诊断模式，禁止恢复猜测参数后自动解锁 |
| 看门狗/复位 | 复位原因、任务活性 | 重新启动仍锁定；报告上次故障，不承诺系统失控期间会执行回位 |

阈值都必须包括单位、测量源、滤波/持续时间、滞回、适用模式与验收记录。电流 ADC 是监测，不等价于硬件短路/快速过流保护。

### 阶段 6：机械映射和开环飞行试验

任务：

- 在翅膀和连杆上贴标记，用高速摄像或角度工装测量舵机角度与翼角关系。
- 测量左右翼的幅度、公共模式、差动模式、相位偏差以及结构共振区。
- 建立控制量到动作的实验映射，下面仅为候选假设：
  - 公共扑翼幅度/频率 → 升力或高度趋势；
  - 左右幅度差或中心偏置 → 滚转/转向趋势；
  - 左右相位差 → 偏航或侧向趋势；
  - 前后机构偏置（若机械结构支持） → 前进趋势。
- 每次只改变一个变量，记录命令、遥测、视频、供电电压和舵机电流。
- 试验顺序固定为：拆翼 → 装翼不通电自由摆动 → 无人台架 → 软约束/系留 → 低能量自由飞行 → 正常动力。

两只执行器不意味着可独立控制滚转、俯仰、偏航和升力。按固定工作点对输入逐一扰动，记录身体角速度/姿态/位移响应，估计局部控制效能矩阵。无法证明有足够控制权的前进/转向/升降命令返回“不支持/未标定”，不能包装为已经实现的完整飞行能力。首版目标仍是完整扑翼与动作试验，动作上线受实验结果约束。

出口条件：

- 有版本化的机械参数表和动作映射表；
- 每个动作都有起始条件、停止条件和安全边界；
- 能从日志重放一次实验并解释急停/失联行为；
- 尚未证明的动作不进入遥控器默认模式。

### 阶段 7：IMU、气压计和状态估计

任务：

- 先验证 LSM6DS3TR-C SPI 读写、WHO_AM_I、量程、ODR、FIFO 和时间戳。
- 固定 IMU 安装坐标、轴向、符号和机体坐标系；写入文档和单元测试。
- 做陀螺零偏、加速度计六面体标定和温漂记录。
- 实现姿态估计和健康度：陀螺积分配合加速度校正，输出四元数/欧拉角、偏置和有效标志。LSM6DS3TR-C 为六轴，无磁力计；绝对航向不可长期观测，不能承诺无漂移偏航保持。
- 扑翼加速度不是纯重力，按模长/振动情况降低加速度校正权重；记录相位相关振动，滤波频带依据实测频谱，避免直接套用多旋翼参数。
- 验证 SPA06-003 I2C 读写和气压高度稳定性；高度功能后置，不得在未验证气压噪声前闭环。
- 先只输出遥测和离线分析，不让估计器直接驱动舵机。

出口条件：

- 静止时姿态漂移、动态振动和采样时间抖动有数据；
- 传感器断线、异常值和饱和可检测；
- 遥测数据可在电脑端绘图并与视频/外部仪器对齐。

### 阶段 8：闭环路线

默认路线是先姿态估计，再决定是否具备姿态稳定条件：

1. **闭环前置**：只记录 IMU、翼轨迹、电流和命令，不闭环；确认机构振动不会使估计失真。
2. **姿态阻尼**：低增益限制角速度/姿态修正，保留强制输出限幅和人工急停。
3. **姿态稳定**：分离公共扑翼、左右差动、相位等控制通道，逐通道启用。
4. **高度辅助（后置）**：只有当前板气压计可用、扰动测试通过且姿态控制有余量时再讨论；用低带宽趋势调节公共幅度/频率。气压受翼流影响，不把气压计单独视为可靠离地高度测量。
5. **翼角/轨迹闭环（可选）**：如果需要真实翼角闭环，下一版增加舵机位置或翼角传感器；仅凭 PWM 目标值不能证明翼角已到位。

所有闭环控制器必须具备：输出限幅、积分抗饱和、传感器失效降级、模式切换斜坡、日志记录和可重复参数版本。

## 6. 参数和协议设计原则

### 6.1 参数分组

- `board`：PWM 引脚、SPI/I2C/ADC 通道、板版本。
- `servo_left/right`：方向、零位、脉宽表、角度限位、速度限制、安全角度。
- `flapping`：轨迹类型、频率上下限、幅度上下限、中心、相位、差动比例。
- `safety`：解锁条件、失联超时、欠压阈值、过流阈值、回安全角速度。
- `radio`：配对 ID、频道策略、控制/遥测周期、重试和加密状态。
- `sensors`：量程、ODR、轴向、校准矩阵、电池分压、电流增益。
- `control`：闭环增益、输出限幅、积分限幅、模式切换条件。

每个参数包含名称、类型、单位、最小值、最大值、默认值、版本和来源；写入 NVS 前进行范围检查。参数分为只允许锁定时更改的标定/安全/通信配置，以及运行时可斜坡更新的控制量。运行帧不写 NVS，避免闪存磨损与控制阻塞。

保存使用完整 blob＋应用 CRC＋NVS commit，读回验证后生效；需要保留旧版本时采用 A/B blob 与版本号。不得只写多个散乱 key 后就宣称原子提交。未标定配置仅允许读取和受限校准，不带翼解锁。

### 6.2 协议兼容

- 所有帧有 magic、版本、长度、会话、序号和校验。
- 接收端拒绝未知版本、过期序号、错误长度和超时帧；不同设备时间戳不能直接相减判定失联。
- 命令与遥测分开编号，协议变更增加版本并保留向后兼容解析。
- 参数写入需要命令确认和回读；急停不依赖参数存储。

### 6.3 第一版公共线格式

第一版选择显式二进制编码，little-endian，单帧不超过 200 字节，使两端无需依赖较大的 ESP-NOW 帧版本。不得直接发送 C struct 内存，因为填充、对齐、float 表示和编译器可能不同。协议文档必须给出逐字节 offset、长度、合法范围和至少一组黄金样例。

公共头按以下顺序编码，共 24 字节：

| 字段 | 长度 | 说明 |
|---|---:|---|
| magic | 2 | 固定字节 `0x42 0x46` |
| version | 1 | 初始 1 |
| message_type | 1 | 见命令表 |
| payload_length | 2 | 不包括头与 CRC |
| flags | 2 | 未定义 bit 必须为 0 |
| session_id | 8 | 飞控建立会话时生成的新随机 ID |
| sequence | 4 | 当前发送方、当前会话内严格递增 |
| request_id | 4 | 请求/响应关联；周期帧可用 0 |

CRC 采用 CRC-32/ISO-HDLC，覆盖公共头及 payload，帧尾 4 字节 little-endian。CRC 仅用于误码/解析保护；来源认证依赖加密配对和会话，不能把 CRC 当加密。测试包括标准输入 `123456789` 的结果 `0xCBF43926`。

| 类型 | 值 | 必需行为 |
|---|---:|---|
| HELLO / SESSION | 1 / 2 | 版本和能力协商，分配会话；不解锁 |
| CONTROL | 3 | 最新控制快照；有效期、mode 和范围检查 |
| ARM_REQUEST | 4 | 独立可靠请求，携带当前会话及确认条件 |
| DISARM | 5 | 请求停止扑翼并锁定 |
| ESTOP | 6 | 高优先级锁存；重复急停仍按幂等停止处理 |
| CLEAR_FAULT | 7 | 只能清除已解除且可清除故障，不顺带解锁 |
| PARAM_GET / PARAM_SET | 8 / 9 | 参数带类型/单位，SET 只在允许状态执行 |
| PARAM_SAVE | 10 | 锁定状态持久化并回读确认 |
| STATUS / EVENT | 11 / 12 | 周期遥测及故障事件 |
| ACK / NACK | 13 / 14 | 带 request_id、结果码；无线发送成功不等于命令执行成功 |
| HEARTBEAT | 15 | 健康信息，不能替代有效 CONTROL 保持运行 |

CONTROL payload 使用整数单位，按以下顺序编码：mode(u8)、reserved(u8)、ttl_ms(u16)、upstream_age_ms(u16)、reserved(u16)、lease_id(u32)、frequency_millihz(u32)、左右 amplitude_centideg(u16×2)、左右 center_centideg(i16×2)、phase_centideg(i16)、左右 trim_centideg(i16×2)、differential_permille(i16)。所有字段在 `protocol.md` 固化。0.01° 只是编码分辨率，不是舵机精度承诺。

动作映射控制使用独立 payload 版本或模式，定义公共扑翼强度、前进请求和转向请求；尚无效能标定时拒绝该模式。急停应采用独立消息，避免普通控制排队导致延迟；不能只依赖 CONTROL 中的一个 bit。

ARM_REQUEST、PARAM_SET、PARAM_SAVE 和 CLEAR_FAULT 需要应用 ACK、超时、有限重试和 request_id 幂等缓存。CONTROL 不逐帧重传、不累积队列，永远以最新有效快照为准；队列满不得丢失已锁存的 ESTOP。

### 6.4 USB 串口和上位机最小工具

USB 采用同一公共帧，以 COBS 编码并用 `0x00` 分隔；解析器有最大帧长、部分帧超时和重新同步能力。外置 UART 桥初始用 115200、8N1；若遥控端采用原生 USB CDC，该串口波特率不作为无线性能依据。先核对遥控端型号和 USB 端口，禁止假设所有 ESP32 都有原生 USB。

上位机建议先用 Python＋pyserial 提供命令行及简单控制面板，不要求首版大型 GUI。Python 环境使用项目 `.venv` 和 `uv`；工具至少包含：

- 端口枚举、连接/断开、版本/能力查询；默认连接后仍锁定。
- 只读状态视图：电池、电流、通信年龄、会话、故障、传感器状态、目标角度。
- 单独的“解锁”“停止”“急停”“清除故障”操作；急停固定位置、始终可见。
- 锁定模式参数编辑、范围校验、读回、导入/导出、显式保存。
- 校准模式左右角度控制，以及扑翼频率/幅度/中心/相位设置；滑块变化先限幅并按固定周期发快照。
- CSV/JSONL 日志、简单趋势图和事件列表；明确区分目标角度与实际反馈。本版没有实际舵机/翼角反馈时显示“无反馈”，不能显示目标值为实测值。

上位机通过定时任务每 20 ms 发当前有效命令，输入和链路活性独立监控。上位机卡死、串口拔出或协议错误时，遥控端按上游过期处理；禁止自动重连后恢复解锁。

### 6.5 会话、新鲜度和配对

- 第一版一机一控，固定共同 Wi-Fi 信道；先检查 SDK 和芯片支持的 ESP-NOW 加密单播接口。飞行时不扫描信道、不同时连接会导致自动换频道的 AP。
- 无实体配对按钮的当前板可通过飞控 USB 诊断会话在锁定状态配置 peer；遥控端由上位机配置。发现广播只用于查找设备，控制必须加密单播并通过 MAC 白名单。
- 密钥按设备生成并通过受控有线配置；日志和参数导出默认隐藏密钥。第一版不实现空中重新配对和 OTA。
- 飞控/遥控端重启、USB 断开或会话结束均清除运行授权；重新 HELLO 获得新 session_id。会话内不允许序号回绕，接近上限先锁定再建立新会话。
- 普通帧只有通过版本、长度、CRC、来源、会话、序号、范围和 TTL 检查才刷新有效控制计时。重复/旧帧/仅 HEARTBEAT 不刷新。
- 同一时间戳不能直接用于两个 MCU 的超时计算。失联以接收端本地单调计时为准；遥控端使用本地时钟测电脑命令年龄，并把 `upstream_age_ms` 带到 CONTROL，超过上游 TTL 必须拒绝。
- 无线排队延迟也需识别：实现 SESSION 阶段时选择“有误差界的时间同步”或“飞控签发带本地到期时间的短期控制 lease”并固化协议。推荐短期 lease：STATUS 带 lease_id，飞控保留其本地到期时间，CONTROL 回传有效 lease_id；过期 lease 不接受运行控制。初始 lease 有效期 150 ms，仅供台架测试，丢失遥测同样将安全停止。
- lease 不替代安全状态和上游过期检测，不允许恢复链路时的缓存 ARM_REQUEST 自动解锁。

STATUS 必须纳入 lease_id 和 lease_valid_for_ms，CONTROL 回传第 6.3 节定义的 lease_id，并在黄金样例中验证；后续 AI 不能自行在一端增删字段。

## 7. 测试和验证矩阵

### 7.1 单元/主机测试

- 角度—脉宽映射、方向、限幅、斜坡和轨迹相位。
- 控制帧编码/解码、CRC、版本、序号、乱序和重放。

### 7.5 首次软件验收目标

下面是台架软件验收目标，不能视为已满足的飞行安全指标：

| 项目 | 通过条件 |
|---|---|
| PWM | 频率相对 333 Hz 误差不大于 1%；脉宽误差目标不大于 5 µs，超标先分析测量和外设分辨率 |
| 控制任务 | 无线满负载下连续 10 分钟无看门狗、越界或无界积压；记录最大 `dt`，重复超过 2 个控制周期即停止并分析 |
| 解锁 | 冷启动、重启、USB 重连、失联恢复都必须锁定；旧会话/旧解锁请求无效 |
| 失联 | 从最后有效帧起，配置超时＋不超过 2 个控制周期内进入安全回位状态；实际回位耗时单独记录 |
| 急停 | 接收到有效 ESTOP 后不超过 2 个控制周期停止周期轨迹；发送到接收的无线延迟单独统计 |
| 上游失联 | 上位机停发，遥控端不能无限续期旧命令；最坏时间包括上游超时＋链路/飞控处理预算 |
| 故障注入 | CRC、会话、长度、参数越界、NVS 损坏、IMU 离线和 ADC 饱和均有测试记录；不产生未授权动作 |
| 机械回位 | 台架记录起始位置、供电、电流和回位时间；只能确认命令已发/等待时间已到，本版不能证明翼已实际回位 |

频率/幅度/安全角/电流阈值按标定数据另行验收。软件目标不达标时不得通过增大时间预算掩盖调度或协议问题。

### 2026-10-21：台架控制台 Wi-Fi 优先，USB-Serial-JTAG 串口回退

范围：

- 台架控制台主设备显式选为 `CONFIG_ESP_CONSOLE_USB_SERIAL_JTAG`：Wi-Fi 未配置或 AP 不可达时，
  编程口上的 USB-Serial-JTAG 虚拟串口照常提供同一套 `esp_console` 命令。
- `bench_main.c` 不再用 `ESP_ERROR_CHECK` 卡住 Wi-Fi 启动：失败只告警并继续起串口控制台，
  避免空 SSID 或路由器不在时板子重启循环、串口也进不去。
- `tools/station/link.py` 增加串口传输与“先 Wi-Fi、失败回退串口”的 auto 模式；TCP 扫描、
  协议与重试逻辑原样保留。串口侧按提示符探测（跳过蓝牙端口、Espressif VID 优先），
  并剥离 REPL 回显的命令行。
- `bf_station.py` 新增 `--serial`、`--method {auto,tcp,serial}`、`--list`；窗口顶栏增加连接方式
  选择、串口下拉框和“刷新端口”，连接后显示实际使用的链路。

关键决策：

- **Wi-Fi 是首选、串口是保底，两者同时存在**。串口不是替代品：Wi-Fi 通则继续用 TCP
  （无电缆、可远程），Wi-Fi 不通时同一套命令从 USB 线走。两条链路共用 `esp_console`
  解析器和命令集，避免行为分叉。
- **Wi-Fi 失败不得阻塞启动**。原实现的 `ESP_ERROR_CHECK(bf_net_wifi_start())` 在 SSID 为空时
  直接 abort，串口回退路径根本没机会起来；改为告警继续。
- **串口探测以提示符为准**。重新枚举后 COM 号会变；发一个空行换取新提示符即可判断，且打开后
  主动拉低 DTR/RTS，不触发芯片复位。
- **auto 模式的错误要能区分链路**。两条都失败时返回“Wi-Fi/TCP: …；串口: …”，
  否则用户无法判断是网络还是端口问题。

构建与测试：

- 台架固件：`scripts/idf.sh -C test/bench -B "$PWD/test/bench/build" build` 通过，
  `bf_bench.bin` 0x6bf70（Wi-Fi + lwIP + USB 串口控制台）。
- Python：`uv run --project tools python -m unittest discover -s test -p "test_*.py"` 25 项通过，

### 2026-10-15：台架接入 flapping 服务 + 上位机扑翼面板

- `src/service/CMakeLists.txt` 把 `flapping` 移出 `if(NOT BF_BENCH)`：台架现在编入轨迹生成器（它无 ESP-IDF 依赖），其余飞行栈（`protocol`/`radio`/`safety`/`telemetry`）仍排除。

- 台架新增顶层命令 `flap <hz> <amp_l> <amp_r> <center_l> <center_r> <phase_deg> <diff> [seconds]`、`flap stop`、`flap`（状态与限幅）。`flap` 走标定路径，两侧未标定即拒绝；被 `flapping_validate()` 拒绝时打印每侧幅度上限及 travel/speed/accel 三项约束，而不是只回一句失败。`hw pulse off` 与 `servo off` 兼作急停（同时停轨迹并关输出）；扑翼运行期间 `hw pulse <us>` 与 `servo <deg>` 被拒绝，避免两条路径争同一个比较值。

- 飞控台架 console（`bf_console.c`）同样是 8，其最长命令 `param set <name> <value>` 只有 4 个 token，本次未改动。
- 上位机新增「扑翼 · flapping service」页：两点标定（下限/上限 µs、calibrated）、限幅（`max_flapping_hz`、`ramp_s`、每侧速度/加速度）、轨迹数值与开始/停止/状态。空输入框不写入；「读取当前值」用 `param get` 回填；标定按 下限→上限→calibrated 顺序写入；写入前先发 `flap stop`（输出打开时参数写入会被固件拒绝）。页面同时按界面上填写的频率与限幅实时估算允许的峰值幅度（与 `flapping_validate` 同两条包络，不含行程限制），避免反复试参数。
- 台架不预置任何标定或放宽后的限幅：默认 `system.max_flapping_hz=1.0`、`servo_*.max_acceleration_dps2=360` 使 1 Hz 下幅度上限仅 9.12°，台架要更大摆幅必须按实测自行放宽，未测量值仍保持未测量状态。
- 验证：`gui.py` 通过 `py_compile` 与真实 Tk 构造、命令拼装断言（限幅+标定序列、勾选未标定时拒绝、非整数脉宽拒绝、非数字限幅拒绝、12 项读取、`flap 2 25 8 0 0 0 0 10` 拼装）；台架固件由使用者在实机烧录，`flap` 命令存在并响应。主机测试与飞控/遥控端构建本次未复跑。

### 2026-10-13：IMU 改用 ST 官方驱动；气压计维持手册实现

  `platform_delay` 三个回调并填入 `stmdev_ctx_t`；IMU 的复位、BDU、地址递增、ODR、量程、
  data-ready 判定与原始值读取全部改走 ST 语义接口，`motion.c` 中不再出现裸寄存器地址或位域。
- 删除 `motion_math.c` 中重复的 `lsm6ds3tr_decode`（换算改由 ST 的
  `from_fs2g_to_mg` / `from_fs250dps_to_mdps` 提供，数值与原先整数运算一致）。

关键决策：

- **气压计不引入第三方驱动**。SPA06-003 找不到可核实的原厂 GitHub 驱动；ESP 组件仓库无
  `spa06`/`goertek` 条目，第三方只有 Adafruit（Arduino `Wire` 依赖）和 PX4（C++ 且绑定
  PX4 device 框架），移植成本高于收益。继续以原厂手册的四阶补偿实现为准，并与 Adafruit 交叉核对。
- **SPI 读必须用单次事务**。ST 参考例程靠手动 GPIO 拉低 CS 横跨"发地址/收数据"两次调用；
  ESP-IDF 硬件 CS 每次事务结束都会释放，照搬会破坏读时序。改用 `command_bits = 8`，地址进
  command phase、数据进同一事务的数据阶段。此结构与原手写驱动一致，未改变总线时序。
- **错误码保真**。平台回调失败时原样回传 `esp_err_t`（ST 只在 ctx 为 NULL 时返回 -1），
  因此 `motion.c` 仍能报出精确错误码；SPI 超时上板后仍为 `ESP_ERR_TIMEOUT`。
- 变更前先更新 `docs/sensors.md`（驱动来源、验证范围、实物反馈），符合"先文档后代码"要求。
  本次不涉及引脚、协议字段、默认值或安全动作，无版本号需要提升。
